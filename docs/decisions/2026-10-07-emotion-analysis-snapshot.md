# 决策：情绪分析依据保存完整快照，而非"可重建依据"

日期：2026-10-07
状态：已落地（`EmotionAnalysisSnapshot`，见 `src/core/models.ts`）

## 背景

作品需要支持保存后回看当时的情绪分析依据、恢复自动建议。旧记录只保留了部分分析信息（`emotion` + `confidence` + `features`），手动改选后还会把自动建议的置信度当作最终标签的置信度展示。需要决定：保存完整分析结果，还是只保存足以按当时规则重建结果的依据（特征 + 规则版本）。

## 比较

| 维度 | 完整快照 | 仅存重建依据（features + 规则版本） |
| --- | --- | --- |
| 记录体积 | 约 0.3–0.5 KB JSON（6 个特征数 + 4 个分数 + 标签/置信度/一句解释 + 版本号），相对 10 秒音频 Blob（数百 KB）可忽略 | 仅省约 0.2 KB，无实际意义 |
| 规则升级兼容 | 任何规则版本下都能如实还原当时结论 | 要求旧版规则代码永久保留且可执行；旧规则被删除或行为漂移后无法重建，实际会退化为"用当前规则重算"——恰好是被禁止的行为 |
| 回看稳定性 | 快照是事实记录，不依赖代码版本与计算确定性 | 重建结果依赖规则实现、浮点细节与重构历史，长期不可靠 |

## 结论

保存**完整分析快照**（`analysis: { rulesVersion, analyzedAt, features, suggestion }`），同时：

- 快照内保留 `features` 与 `rulesVersion`，允许用户**显式**选择"按当前规则重新分析"——结果标注为当前规则的新依据，不冒充保存时的结论；
- 回看时若 `rulesVersion` 与当前规则不一致，界面明确提示"展示的是保存时的原始结论，未按当前规则重新计算"；
- 最终标签与自动建议分开存储（`emotion`/`emotionSource` vs `analysis.suggestion`），手动标签不保存自动建议的置信度；
- 早期记录缺少快照时如实显示"未记录分析依据"，不编造零分、不猜测来源；旧记录再次保存时按新 schema 如实落库（`emotionSource`/`confidence` 未知则留空），历史 `features` 原样保留。
